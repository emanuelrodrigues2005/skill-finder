# F0 — Pré-requisitos e sandbox

<!--ISSUE:Validar o sandbox AWS Academy (K1–K14)-->
## O que entrega

Prova, em uma sessão de laboratório, que a máquina e a conta fazem tudo o que o plano assume:
credencial de sessão `voclabs`, região, key pair, `LabRole`/`LabInstanceProfile`, ECR, S3 e RDS
respondidos, com uma linha datada por item em `docs/evidencias/sandbox.md`.

## Critérios de aceitação

- [x] `aws sts get-caller-identity` retorna ARN contendo `assumed-role/voclabs/`
- [x] K1, K2, K3 (+`ImportKeyPair`), K6, K7, K10, K11, K14 registrados com data, comando e resultado
- [x] `docs/evidencias/sandbox.md` com 8+ linhas no formato `# | data | comando | resultado | disponível? | o que muda no plano`
- [x] privada do key pair em `~/.ssh/projeto2` com `chmod 400`, fora de `/mnt/c`
- [x] `.gitignore` cobre `.env`, `*.tfstate*`, `*.auto.tfvars`, `*.pem`, `.terraform/`, `node_modules/`, `coverage/`

## Verificação

```bash
aws sts get-caller-identity --query Arn --output text   # assumed-role/voclabs/...
aws configure get region                                # us-east-1
terraform version                                       # >= 1.10
aws ec2 describe-key-pairs --key-names projeto2         # 1 item
stat -c %a ~/.ssh/projeto2                              # 400
grep -cE '^\| K' docs/evidencias/sandbox.md             # >= 8
```
