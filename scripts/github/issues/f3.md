# F3 — Infraestrutura como código

<!--ISSUE:feat(infra): base do Terraform com backend S3 e rede-->
## O que entrega

A base do Terraform da **Opção 1** (`docs/01` §5.1), versionada em `infra/`: `required_version` ≥ 1.10,
provider AWS fixado em `us-east-1`, backend S3 com `use_lockfile`, variáveis, `data` sources do IAM
pré-existente do lab (nenhum recurso `aws_iam_*`), key pair da F0 e security group com 80 aberto e
22 restrito ao CIDR parametrizado.

## Critérios de aceitação

- [ ] `infra/versions.tf`, `backend.tf`, `variables.tf`, `data.tf`, `keypair.tf`, `network.tf`, `terraform.tfvars.example` sem valor sensível
- [ ] `data "aws_iam_instance_profile" "lab"` e `data "aws_iam_role" "lab"` — **zero** `resource "aws_iam`
- [ ] `allowed_ssh_cidrs` como variável (22 fechado por padrão); justificativa escrita se abrir para o mundo
- [ ] bootstrap do bucket de estado documentado no runbook, explicitando que ele **não** pertence a este state
- [ ] `grep -rnE '([0-9]{1,3}\.){3}[0-9]{1,3}' infra/` sem IP literal

## Verificação

```bash
terraform -chdir=infra fmt -check -recursive      # exit 0
terraform -chdir=infra init
terraform -chdir=infra validate                   # "Success! The configuration is valid."
grep -rn 'resource "aws_iam' infra/               # vazio
git status --short                                # nenhum .tfstate, nenhum .pem
```

## Dependências

- Depois da suíte de testes e da toolchain (F0).

## O que entrega

Transforma "roda na minha máquina" em "criado por Terraform, com estado remoto, app respondendo no
IP público e destruível sem órfãos": `aws_instance` `t3.small` com `user_data` que instala
Docker/Compose e habilita o serviço, volume EBS `gp3` idempotente, repositório ECR com scan e
*lifecycle* de 5 imagens, e **exatamente as 4 saídas do *seam*** (`host_public_ip`,
`ecr_repository_url`, `state_bucket`, `target_port`).

## Critérios de aceitação

- [ ] `terraform apply` conclui sem erro, **sem** `-auto-approve`, a partir de diretório limpo (log em `docs/evidencias/f3-apply.txt`)
- [ ] segundo `terraform plan` = "No changes."; `terraform state list` ≥ 8 e nenhum `aws_iam_*`
- [ ] `curl -fsS http://<ip>/healthz` = 200 e a SPA carrega no navegador
- [ ] `ssh -i ~/.ssh/projeto2 ubuntu@<ip> 'docker compose -f /opt/app/compose.yaml ps'` mostra `api`/`web` healthy
- [ ] dados sobrevivem a `stop`/`start` da instância (EBS)
- [ ] **`terraform destroy` exit 0 sem órfãos**: `describe-instances`/`describe-volumes` sem recurso com a tag do projeto e `plan` seguinte limpo
- [ ] bucket de estado preservado após o `destroy`; `docs/runbook-operacao.md` com subir, implantar, destruir e encerrar sessão

## Verificação

```bash
terraform -chdir=infra plan -out=plan.out
terraform -chdir=infra apply plan.out
curl -fsS http://$IP/healthz
terraform -chdir=infra state list | wc -l
terraform -chdir=infra destroy
aws ec2 describe-instances --filters "Name=tag:project,Values=skill-finder" --query 'Reservations[].Instances[].State.Name'
aws s3 ls s3://<state_bucket>/projeto2/
```
