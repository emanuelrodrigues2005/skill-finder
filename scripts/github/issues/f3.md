<!--ISSUE:F3.7 — Gate: apply, smoke e destroy sem orfaos-->
## O que entrega

A prova de fase: o ciclo inteiro executado uma vez, cronometrado, com evidência em `docs/evidencias/`.

`destroy` de resíduo → `init/plan/apply` → build e push das duas imagens com tag = SHA → `scp` dos composes e do `.env` → `compose pull && up -d` → `prisma migrate deploy` → ingestão pelo admin endpoint → smoke na borda → `destroy` → varredura de órfãos.

É o gate de saída da F3 e o que destrava a F4.

## Critérios de aceitação

- [ ] `apply` < 10 min; ciclo total registrado em `f3-apply.txt` / `f3-smoke.txt`
- [ ] `/healthz` na borda responde `ok` em JSON
- [ ] `/readyz` responde `ok` e **reprova** (503) com o Postgres parado
- [ ] `GET /api/v1/categories` >= 1 (catálogo real, não fixture)
- [ ] `POST /api/v1/admin/ingest` responde 202 com token e 401 sem ele
- [ ] `.env` em `/opt/app` com permissão 600
- [ ] `terraform destroy` exit 0 e nenhum recurso com a tag do projeto vivo
- [ ] bucket de state sobrevive ao destroy
- [ ] print datado da SPA em `f3-url.png`
- [ ] nenhum segredo nas evidências

## Verificação
